# Контрольные вопросы - Практическая работа «ООП в PHP»

## 1. Чем класс отличается от объекта?

Класс - это шаблон (чертёж), который описывает свойства и методы сущности. Объект - конкретный экземпляр класса, созданный оператором `new`. Один класс может породить сколько угодно объектов, и каждый хранит свои собственные данные.

```php
class Car { public string $brand; ... } // класс
$c1 = new Car('Lada'); // объект
$c2 = new Car('Toyota'); // другой объект того же класса
```

## 2. Для чего нужен конструктор и когда он вызывается?

Конструктор - метод `__construct()`. Он задаёт начальное состояние объекта. Вызывается **автоматически** один раз в момент создания объекта через `new`. В нём обычно заполняют свойства.

```php
$u = new User(1, 'Анна', 20); // здесь PHP сам вызывает __construct
```

## 3. Что означает `$this` и почему он недоступен в статических методах?

`$this` - это ссылка на текущий объект внутри его метода. Через `$this->name` обращаются к свойствам конкретного экземпляра.

В статических методах (`static`) объект не создан - метод вызывается у класса (`Math::sum(2,3)`), а не у объекта (`$obj->sum()`). Поэтому `$this` там не существует: не к чему обращаться. Статические методы работают с `self::` и статическими свойствами.

## 4. Чем отличается `$obj2 = $obj1` от `$obj2 = clone $obj1`?

- `$obj2 = $obj1` — обе переменные указывают на **один и тот же** объект. Изменение через `$obj1->x` видно и через `$obj2->x`.
- `$obj2 = clone $obj1` — создаёт **независимую копию** объекта. Изменения `$obj1` не затрагивают `$obj2` и наоборот.

В PHP объекты передаются по ссылке на объект, поэтому обычное присваивание копий не делает.

## 5. Чем статическое свойство отличается от обычного? Как к нему обратиться?

Статическое свойство объявляется через `static` и принадлежит **классу**, а не конкретному объекту. Оно одно на все объекты класса.

Обычное свойство принадлежит объекту - у каждого объекта своё.

К статическому свойству обращаются через `ClassName::$property` или `self::$property` внутри класса. К обычному - через `$obj->property`.

```php
class User {
    public static int $count = 0; // общее для всех
    public string $name; // у каждого своё
}
User::$count++;
```

## 6. Что такое readonly-свойство и когда его можно присвоить?

`readonly` (PHP 8.1) - свойство, которое можно задать **только один раз**, и только внутри конструктора (или в том же объекте до первого чтения). После этого изменить его нельзя - PHP выдаст `Error: Cannot modify readonly property`.

Обычно readonly делают для идентификаторов, которые не должны меняться после создания объекта: `$id`, `$createdAt` и т.п.

## 7. Что такое продвижение свойств в конструкторе?

Продвижение свойств (constructor promotion, PHP 8.0) - это когда свойство объявляется прямо в параметре конструктора с модификатором доступа. PHP сам создаёт свойство и присваивает ему значение.

```php
public function __construct(public string $name) {}
```

Это равносильно:

```php
public string $name;
public function __construct(string $name) { $this->name = $name; }
```

Код короче, без дублирования.

## 8. Как реализовать цепочку вызовов методов?

Метод должен возвращать сам объект (`return $this;`), тогда следующий метод можно вызывать сразу:

```php
$calc->add(5)->multiply(3)->add(1);
```

У методов указывают тип возвращаемого значения `static` или `self`, чтобы подсказать IDE и сохранить класс при наследовании.

## 9. Назовите три магических метода и случаи, когда PHP их вызывает.

1. **`__construct()`** - при создании объекта через `new`.
2. **`__toString()`** - когда объект используется в строковом контексте (`echo $obj`, конкатенация).
3. **`__get($name)` / `__set($name, $value)`** - при обращении к недоступному или несуществующему свойству (`$obj->foo`).

Также есть `__call`, `__clone`, `__destruct`, `__isset`, `__unset`.

## 10. Чем `protected` отличается от `private` при наследовании?

- `private` - доступно **только внутри класса, где объявлено**. В наследниках уже не видно.
- `protected` - доступно внутри своего класса **и в классах-наследниках**.

```php
class A {
    private   $x; // B не увидит
    protected $y; // B увидит через $this->y
}
class B extends A { /* ... */ }
```

Снаружи (через `$obj->`) ни `private`, ни `protected` недоступны.

## 11. Что делает ключевое слово `final`?

- `final class X` - класс нельзя наследовать.
- `final public function f()` - метод нельзя переопределить в наследниках.

Это защищает важную логику от изменений в дочерних классах.

## 12. Как работает `spl_autoload_register`?

Функция регистрирует пользовательский загрузчик. Когда PHP встречает обращение к ещё не загруженному классу (`new SomeClass()`, `SomeClass::method()`), он вызывает зарегистрированную функцию и передаёт ей имя класса. Функция по имени вычисляет путь к файлу и делает `require`.

```php
spl_autoload_register(function (string $class) {
    $file = 'src/' . str_replace('\\', '/', $class) . '.php';
    if (is_file($file)) require $file;
});
```

Можно зарегистрировать несколько загрузчиков - PHP перебирает их, пока класс не загрузится.

## 13. Как стандарт PSR-4 связывает пространство имён и путь к файлу?

PSR-4 говорит: пространство имён соответствует папке, а имена классов внутри него - файлам.

Например, если в `composer.json` задано `"App\\": "src/"`, то:

- класс `App\Models\User` ищется в файле `src/Models/User.php`;
- класс `App\Services\Greeter` — в `src/Services/Greeter.php`.

Правило: имя класса без префикса превращается в путь, где `\` заменяется на `/`, и добавляется `.php`. Один класс — один файл, имя файла = имя класса.

## 14. Когда нужно выполнять `composer dump-autoload`?

- после создания `composer.json` (первый раз);
- после добавления новых классов в существующие папки PSR-4 - обычно не нужно, Composer сам их найдёт; но если используете `classmap` autoload - нужно;
- после изменения секции `autoload` в `composer.json` (добавили новый префикс, новую папку, сменили путь);
- после переименования классов или пространств имён, если включён `classmap`.

Префикс PSR-4 после `dump-autoload` запоминается в сгенерированном файле `vendor/composer/autoload_psr4.php`, и при изменении префикса в `composer.json` нужно перегенерировать этот файл, иначе Composer будет искать классы по старому правилу.
